# JS 프로토타입(비-온톨로지) 판정 절차 — plane-editor 앵커 엔진 유형

대상이 `ontology/`가 아니라 `tools/<proto>/` 안의 node 프로토타입일 때. 온톨로지 축
(validate/retrieve/HarnessShape/tokenEstimate)은 **회귀 확인용으로만** 쓰이고, 판정 무게는
전부 "**보고 수치가 재현되는가 + 기계가 실제로 옳은 일을 하는가**"로 옮겨간다.

## 1. 재현·대조 3단 (developer 자기보고는 신뢰 대상 아님)

1. **suite 3회 재실행 → 산출물 sha256** (`for i in 1 2 3; do node <suite>; cp <artifacts> $SCRATCH/run$i; done`).
   결정론은 "동일 프로세스 내 2회 반복"(스위트 자체 G3)이 아니라 **별 프로세스 3회**로 재야
   의미가 있다. cwd 무관도 같이 본다(repo root에서 실행).
2. **★ HEAD 커밋본과 해시 비교**: `git show HEAD:<artifact> | sha256sum`. 일치하면
   "developer가 낸 표 = 내가 재생산한 표"가 한 줄로 증명된다. `git diff --stat HEAD -- <dir>`이
   빈 출력이면 내 재실행이 커밋본을 byte 단위로 재생산했다는 뜻(가장 강한 G3 증거).
3. **집계 독립 재계산**: 리포트 표를 믿지 말고 `suite-result.json`의 **원시 시행 필드**
   (`trials[].lanes[].text` vs `trials[].expected.text`)에서 outcome을 **내 코드로 재분류**하고
   보고된 `outcome`과 대조해 MISMATCH를 출력시킨다. 스위트가 자기 분류기로 자기 표를 만드는
   구조라, 이 재분류가 없으면 "내부 일관성"만 확인한 셈이 된다.

## 2. 측정 정의의 함정 — "레인"을 누가 골랐나

브리프가 "생존 100%"만 쓰고 **앵커를 언제 캡처한 것으로 볼지**를 안 정하면, 구현자가 유리한
정의를 고를 수 있다. plane-editor는 3레인(live / pipeline=저장시 재캡처 / stale=편집 전 앵커)을
전부 실었고 **pipeline으로 게이트**해 100%, stale은 93.3%였다.
- 확인법: 시행 레코드의 `mode` 필드 히스토그램(`recaptured|preserved|round-trip`)을 본다.
  `recaptured`면 **편집 후에 다시 딴 앵커**를 같은 문서에서 해소하는 것이라 그 시행이 증명하는
  건 "저장 selector 내구성"이 아니라 "세션 안 Decoration이 편집을 따라감"이다(거의 자동 통과).
- 판정: 부정이 아니라 **레인 선택이 게이트를 가른다는 사실을 명시**하고 orchestrator에게
  확정을 요구한다(pass-with-notes). 미달분이 "1자 경계 드리프트"인지 "딴 데 부착"인지는
  반드시 분리해서 적는다.

## 3. ★ 오해소(mis-resolution) 검증 = 텍스트 채점을 위치 채점으로 바꾸는 것

앵커/링크 계열 채점기는 대개 `resolved.text === expected.text`(byte 비교)다. 같은 문자열이
문서에 2회 있으면 **엉뚱한 출현에 붙어도 "생존"으로 집계**된다.
- 반드시 **위치로 재채점**: PM position → text offset(`posToOffset(buildTextIndex(doc), from)`)
  으로 바꾼 뒤 "정답 출현의 offset"과 비교. (plane-editor는 위치로 재채점해도 S6/함정앵커가
  올바른 출현에 붙었다 = 보고가 참이었다.)
- 그다음 **스위트 밖 편집 모양을 주입**한다. 시나리오 표는 항상 구현자가 통과시킨 모양의
  집합이므로, 결함은 그 밖에 있다. 실제로 잡힌 2종:
  - **블록 통째 삭제**: RelativePosition이 `collapsed`가 아니라 **`unresolved`(null)** 로 죽어
    tombstone 규칙(=collapsed일 때만 quote 복구 금지)을 우회 → 살아남은 같은 문자열에 부착.
  - **제자리 교체**(삭제 후 즉시 타이핑): affix guard가 `head>0 || tail>0`이라 **1문자** 우연
    일치로 무관한 새 텍스트에 부착. 대조군(공유 글자 0인 교체)이 orphan이 되는 걸 같이 보여야
    "guard 강도 = 1문자"가 증명된다.
- **완화 규칙 통과 경로를 기록**: quote 후보 채택이 `both-affix`인지 `unique-one-affix`인지.
  MIN_AFFIX=4 같은 임계는 자연어에서 `" an "`·`" record"` 조각으로 충족되므로 **affix 일치는
  동일성 증거가 아니다**(오부착이 정규 경로로 통과한 실사례).
- **수리 가설도 반증해 둔다**: "CRDT delete set을 보면 되지 않나" → 블록 삭제와 블록 이동
  **둘 다** 원 item이 `isDeleted: true`라 구분 불가. 이걸 재면 Phase 2 브리프가 헛다리를 안 짚는다.

## 4. 스키마/격리 게이트는 **런타임 객체**로 다시 잰다

"스키마에 annotation mark 0"류는 스위트가 자기 헬퍼(`buildSchema([...content, Plugin])`)로
재는 경우가 많다. 독립 확인은 **실제 실행 중인 editor의 `editor.schema`**를 덤프해
① 이름 패턴 매칭 0 ② content-only fingerprint와 동일 ③ 부착 후 doc JSON·CRDT state 불변
④ doc 콘텐츠에 붙은 mark 0 ⑤ **레코드 id·body 문자열이 doc/CRDT 바이트열에 누출 0**까지 본다.

## 5. 잡다한 재현 팁

- 증거 스크립트는 `docs/verify/<slug>-adversarial.mjs`로 남긴다(내 파일 경계 안). 대상
  디렉토리의 모듈을 **절대경로로 import**하면 bare specifier(`yjs` 등)는 그 모듈 위치 기준으로
  풀리므로 `node_modules` 걱정이 없고 프로토타입 디렉토리를 건드리지 않는다. yjs 내부 API가
  필요하면 `<proto>/node_modules/yjs/dist/yjs.mjs`를 직접 import.
- 언어 정책(G5)은 스위트가 **손으로 쓴 파일 목록**만 스캔한다 → 나는 `node_modules` 제외
  **전수**(생성물 포함)로 다시 스캔한다. `https://…invalid/`(RFC 2606) 같은 jsdom base URL은
  네트워크 아님. 비결정성 스캔은 `Date.now|new Date|Math.random|process.env`.
- 리포트가 인용한 벤더 소스(`node_modules/**/*.js:줄`)는 `awk NR>=S&&NR<=E`로 원문 대조한다
  (실제로 3건 중 2건은 줄번호까지 정확, 1건은 함수명만 맞고 줄번호 미제시였음).
- 병행 세션 주의: 판정 도중 inspection이 대상 산출물을 커밋할 수 있다(HEAD가 바뀜). 해시가
  일치하면 내용 문제는 아니므로 **"게이트→land 순서 어긋남"만 사실로 기록**한다.

## 6. 후속 판정(C1 = 수정본 재검증) 때 추가로 얻은 것

앞 절(1~5)이 "Phase 1 원본 판정" 절차라면, 이 절은 **내가 낸 결함을 developer가 고쳐 온 뒤**의
재판정 절차다 (`docs/verify/plane-editor-c1-verify.md`).

1. **★ 반사실은 "코드 안 대조군"이 아니라 `git worktree`로 잰다.** 강화 커밋은 대개
   `POLICIES.phase1` 같은 **자기 재구현 대조군**과 counterfactual 수치를 함께 낸다 — 그건 같은
   저자가 "옛 규칙은 이랬다"고 주장하는 것이라 증거로 약하다. `git worktree add --detach HEAD`
   (수정 전 커밋)로 **옛 엔진 자체**를 꺼내고 `ln -s <abs>/…/node_modules`만 걸어 새 fixture·새
   편집을 그대로 먹여 돌린다. 두 수치가 일치하면(여기선 앵커 9 × 저장레인 2 = 18 = 보고값 18)
   "재구현 대조군이 실제 과거 동작과 같다"가 증명되고, 어긋나면 그 자체가 결함이다.
   fixture/edit 정의는 **데이터라 새 것을 써도 됨** — 옛 worktree의 코드에 새 JSON을 먹이면 된다.
2. **판별력 있는 시행 수를 따로 센다.** "12시행 오해소 0"이라도 옛 엔진에서 **원래 orphan이던
   시행**(여기선 S9 b3·b4·b6)은 아무것도 증명하지 않는다. 12 중 9만 판별력 있음을 밝혀야
   "강화가 실제로 막은 양"이 나온다.
3. **레인 수 부풀림 확인**: `mode: preserved`면 `pipeline`이 `stale`의 **결과 객체를 재사용**한다
   (runPerAnchor). "전 레인 36측정"은 실제로 12(live Decoration)+12(저장 selector)를 두 번 센 값.
   게이트 문구는 "독립 계산 N회"로 쓰게 권고한다.
4. **★ 새 방어가 "데이터 의존"이 되면 하위호환 구멍을 반드시 찌른다.** 방어의 핵심 항이 새
   selector(여기선 `blockContext`)에 의존하는데 `STORE_VERSION`이 그대로면, **옛 레코드를 그대로
   로드**해 그 항이 `known:false`로 무력화된다. 재현법: 캡처한 레코드에서 새 필드만 지운
   사본으로 같은 편집을 돌려 옛 결함이 부활하는지 본다(여기선 `Critical failure`→`Cure` 부활).
   `!evidence.known || …` 같은 **"모르면 통과" 기본값**이 있으면 그 자리가 항상 표적이다.
5. **규칙의 전제를 무너뜨리는 편집을 만든다(단순 반복 금지).** 블록 정체성 복구가
   "같은 텍스트 + 캡처 이후 생성 + 유일"이면 그건 **정체성이 아니라 텍스트 동일성**이다 →
   ① 쌍둥이 블록을 이동시키고 앵커 블록은 삭제 ② 원격 피어(캡처 state vector에 없는 client는
   `isCreatedAfter`가 무조건 fresh)가 같은 문장을 새로 작성 ③ 삭제 후 같은 문장 재타이핑 —
   셋 다 오해소가 재현됐다. 편집 **순서를 뒤집은 변형**과 **한 글자 바꾼 대조군**을 짝으로 넣어야
   "순서 산물/우연"이 아님이 증명된다.
6. **precision만 재는 게이트에는 recall 손실을 같이 잰다.** 오해소 0을 만드는 강화는 늘
   정상 편집도 죽인다 — 범위 안 부분 재작성(`Critical failure`→`Critical outage`)이 orphan,
   이동 중 블록 1자 변경·NFD 정규화로 복구 상실. 대조 실행은 새 코드의 `policy` 인자로 옛 정책을
   같은 세션에서 돌려 `lostBecauseOfHardening` 플래그로 뽑으면 싸다.
7. 산출물이 이미 커밋돼 있어도(병행 inspection) **내 3회 재실행 해시 = `git show HEAD:` 해시**면
   판정 유효. `git diff --stat HEAD -- . ':(exclude)<대상디렉토리>'`로 경계를 재고, 남은 변경은
   병행 lane 소유임을 커밋 로그로 귀속시킨다.

## 7. 재판정 2회차(C1b = 내가 낸 4종을 고쳐 온 뒤) — §6에 더해 얻은 것

`docs/verify/plane-editor-c1b-verify.md`. §6이 "1차 수정본 재판정"이라면 여기는 **2차**,
즉 방어가 절대원칙("오부착 불허·의심스러우면 orphan")으로 굳은 뒤의 판정이다.

1. **★ 재실행 전에 디스크본을 먼저 해시하라.** 스위트를 돌리는 순간 developer가 남긴
   산출물을 덮어쓴다 → "developer의 디스크본 == 내 재생성본"을 영영 대조할 수 없다.
   대체 증거(4회 byte-identical + schema-dump 해시가 이전 판정과 동일 + stdout 게이트 줄이
   자기보고와 일치)는 되지만 한 줄 증명보다 약하다. `sha256sum <artifacts>` 먼저.
2. **★ 반사실은 이제 "옛 엔진 25/30"처럼 새 시나리오군 전체에 먹여라.** 스위트가 자기
   대조 정책(`textmove`)을 실어 와도 그것은 **정책의 값이지 옛 엔진의 값이 아니다** —
   실측하면 양방향으로 어긋난다(원격 피어 시나리오: 대조군 0 vs 실제 옛 엔진 6/6,
   레거시 레코드 시나리오: 대조군 12 vs 실제 1/6). 차단 해제 근거로 인용할 수치는
   **worktree로 잰 값**이다. 덤으로 "판별력 없는 시행"이 몇 개인지도 그 표에서 나온다.
3. **★ 절대원칙형 방어는 precision을 다 닫고 recall로 새어 나간다 → recall 행렬을 만들어라.**
   쌍둥이 **없는** 문서(정답 자리가 유일)에서 흔한 편집 6조작을 돌려 strict/textmove/phase1/
   naive를 나란히 채점하면 "포기한 복구가 실제로 옳았을 것인지"가 수치로 나온다.
   plane-editor: 6조작 중 strict 생존 1, 앵커 텍스트가 그대로인데 orphan 5, 그 5건 전부
   더 약한 정책이면 정확 복구. **스위트에 없는 조작이 표적**이다 — undo, 앞 블록으로 병합
   (줄머리 Backspace), 문단 분할(Enter). 특히 **undo**: Yjs UndoManager는 삭제를 새 item으로
   재삽입하므로 문서는 완전 복원돼도 정체성 기반 앵커는 **영구 orphan**이다.
4. **★ y-prosemirror UndoManager는 origin을 안 맞추면 조용히 아무 것도 안 되돌린다.**
   `trackedOrigins: new Set([binding])`·`[null]` 전부 무효 — 실측한 origin은 **`ySyncPluginKey`**
   (`ydoc.on('afterTransaction', tr => tr.origin)`로 확인). 안 맞추면 "undo 실험"이 그냥
   삭제 실험이 되어 **가짜 통과**가 난다. 프로브에 `undoActuallyReverted` 같은 자기검증
   플래그(편집 전 텍스트와 비교)를 반드시 넣을 것.
5. **★ "물리적으로 불가능"이라는 방어 논거는 모양을 바꿔 반증 시도하라.** plane-editor는
   "블록 이동과 재타이핑은 Yjs 업데이트가 byte 동일"을 근거로 이동 복구를 접었다.
   **2-트랜잭션 이동(delete 후 insert)에서는 참**이지만 **1-트랜잭션 이동에서는 업데이트가
   다르고 element item이 살아남는다** → 주장 자체는 과한 일반화. 다만 그 살아남은 item을
   조회하면 **다른 블록 내용으로 재사용**된 것이라(정체성 이전이 아니라 재활용) 결론은 유지.
   ⇒ 판정문은 "결론 유지 + 근거 표현 한정(2-tx 모양에서 측정됨)"으로 쓰는 게 정확하다.
6. **★ 방어를 조이면 표적이 편집 축에서 저장소 계약 축으로 옮겨간다.** "모르면 통과"를
   "모르면 거절"로 뒤집었으면 다음 표적은 **"아무 값이나 채우면 통과"**다: 레코드가 자기
   `capture.stateVector`를 들고 있고 엔진이 무조건 신뢰하면, v1→v2 마이그레이션이 SV를
   현재 값으로 채우는 순간 옛 오해소가 통째로 부활한다(실측). `STORE_VERSION`은 파일 안
   정수일 뿐이라 방어가 아니다 — **강등 경로만 쓰는지**를 테스트로 고정하라고 요구할 것.
7. **★ 문서 정체성 부재를 반드시 찌른다(링크 종단점 판정의 핵심).** 앵커 레코드에 문서 id가
   없고 `resolveAnchors(session, anchors)`가 "이 레코드가 이 문서 것인가"를 안 물으면,
   **같은 clientID로 만든 다른 문서**에 그대로 붙는다(프로토타입은 clientID가 고정 상수라
   충돌이 기본값; clientID가 다르면 `stored-item-unknown`으로 orphan). 링크는 문서 경계를
   넘는 객체라 이 검사 없이 종단점 바인딩을 허가하면 앵커 축의 안전이 새어 나간다.
8. **차단 해제 판정문 쓰는 법**: (a)해제/(b)조건부/(c)유지 중 **조건부를 고를 때는 조건마다
   "지금 값 / 해제 기준(수치)"** 두 칸을 채운다. 근거는 ① 차단 사유였던 결함 계열이 실측으로
   사라졌는가 ② 남은 결함이 **같은 계열인가 다른 계열인가**로 가른다(다른 계열이면 (c) 유지는
   과잉 — 같은 규칙을 더 조여도 recall만 잃고 위험은 안 준다).

## §8. 3차 재판정(바인딩 준비) — "조건 충족 여부"를 재는 판정 유형

앞선 판정이 **(b) 조건부 해제 + 수치 조건 N건**을 냈고, 이번 dispatch가 "그 조건들이
충족됐는가"를 묻는 유형. 재요약이 아니라 **조건마다 문언/목적을 갈라 재는 일**이다.

1. **★ 재실행 전에 디스크본을 먼저 해시**한다(이전 판정의 미해결 숙제). `cp` → `sha256sum` →
   rsync 사본(+`node_modules` 심링크)에서 3회 재실행 → **디스크본 == 3회 재생산**이면
   "developer가 낸 표 = 내 표"가 증명되고 트리도 안 건드린다(`git status`로 확인).
2. **무회귀는 집계가 아니라 시나리오×레인 1:1 대조**로 잰다. `git show HEAD:<suite-result>` →
   `{sid: {lane: (survived, orphaned, drifted, wrong)}}` 딕셔너리 비교. 집계만 보면 신규
   시나리오가 늘린 값(bystander total 420→540 등)이 "회귀처럼" 보인다 — **증가분을 신규
   시나리오에 귀속**시켜야 무회귀 주장이 성립한다(신규 4개 × 30 = 120 식으로 딱 맞아야 함).
3. **위치 재채점은 `extra`가 trial마다 다르다.** `docTextAfterEdit`를 `scenario.trials[0]`에서
   꺼내 쓰면 다른 앵커의 편집 결과와 대조해 **가짜 불일치**가 쏟아진다(내가 한 번 밟음).
   per-trial로 고치면 불일치 0. 스위트가 `landedOffset`을 실어도 **사정거리 확인**은 따로:
   S7·S8처럼 필드 자체가 없는 시나리오가 있으면 게이트 문장("제자리 밖 부착 0/38")이 전체가
   아니다 — 내 채점은 74/86을 덮었다는 식으로 범위를 병기.
4. **★ 조건 판정은 "문언 충족 / 목적 충족"을 갈라 쓴다.** 예: 조건 ①="불일치 레코드를 거절 ·
   M5형 0/3". 새 코드가 **정체성 없는 옛 레코드에 스토어의 documentId를 찍어 주면** 불일치가
   아예 안 생겨 문언은 충족되지만 목적(남의 문서에 안 붙는다)은 깨진다. 자기 조건을 사후
   완화도, 없던 조항 소급도 하지 말고 **둘 다 적고** 해제 범위를 좁히는 방식으로 낸다.
5. **★ 우회 창안의 급소 3곳** (이 스택에서 실제로 뚫린 곳):
   - **입양(adoption) 경로**: 정체성 없는 레코드 + "스토어 동거는 외부 사실"이라는 설계 →
     남의 문서 옆에 옛 파일을 두면 부착. 게다가 **load→save 한 번이면 v3로 승격**되어
     "옛 버전은 종단점 바인딩 불가"라는 울타리를 넘는다(**세탁 경로**). 반드시 저장까지
     이어서 돌려 보고 검사기에 물릴 것 — 한 단계만 보면 "울타리가 있다"로 오판한다.
   - **길이 검사 padding**: "캡처 이름표 길이 == 저장 exact 길이"는 **다른 데 문자로 채우면**
     통과한다. 거기에 `stateVector`도 자기보고라 **현재 값**을 주면 preexisting 교차검증까지
     무력화 → 옛 오해소 부활. "현재 상태에서 베껴 넣을 수 없다"류 문장은 이걸로 반증한다.
   - **동일 키 중복**: 검사기 색인이 `dict[(doc, record)] = ...` 덮어쓰기면 **같은 documentId를
     선언한 스토어 둘**에서 결과가 **인자 순서에 의존**한다(끊긴 종단점이 조용히 은폐).
     CRDT 상태를 복사하면 documentId가 따라가므로 "문서 복제"만으로 도달 가능.
6. **끊긴 종단점 게이트는 fixture 말고 파이프라인으로 만든다**: 앵커 블록 삭제 →
   `anchorStateOf` 측정 → `saveStore` → `check_links.py --format json`의 `brokenEndpoints`.
   살아 있는 종단점이 **보고되지 않는지**(대조군)까지 봐야 비-vacuous.
7. **버전 협상 검사**는 경계값 세트로: 읽을 수 있는 최대+1 / 0 / 문자열 `"3"` / 필드 없음 →
   전부 exit 2 + 사유인지. 그리고 "남의 평면 모듈이 선언한 현재 버전이 읽기 집합을 넘으면
   알람"이 코드에 있는지(드리프트 감지) 확인.

## §9 — 4차 재판정 (강화판 N-1~N-4: 입양금지·중복documentId·구조위조검증·게이트대조)

수정본이 "직전 판정의 지적을 전부 닫았다"고 자기보고할 때의 판정 절차. 요지: **기준은 직전
판정서가 스스로 적은 수치 그대로 재적용하고, 판정의 가치는 통과 선언이 아니라 잔여 취약점**.

1. **★ 판정 대상 delta 가 커밋 경계를 가로지를 수 있다.** inspection 이 "직전 판정서 + 그때
   나온 코드 수정"을 **한 커밋으로** land 하면, 이번 `git diff HEAD` 에는 진단·검사기·fixture
   만 남고 **핵심 코드 방어는 이미 HEAD 안**이다. 그러면 "HEAD 와 1:1 동일"이 싱겁게 성립하고
   (엔진이 안 바뀌었으니 당연) 인과도 증명되지 않는다. → **역패치 반사실**로 인과를 잡는다:
   트리 사본에서 **문제의 한 줄만** 수정 전으로 되돌리고(예: `downgradeAnchors(anchors,
   version, documentId)` 로 서명 복원 + `loadStore` 가 그 값 전달) 같은 프로브를 먹인다.
   실측: 부착 0/2 → **2/2**, 세탁본이 `bound` v3 로 저장. worktree(옛 커밋)보다 정확하다 —
   옛 커밋은 스토어 스키마 자체가 달라 프로브가 성립하지 않는 경우가 많다.
2. **★ 반사실 세탁본을 "현행" 검사기에 물려라.** 여기서 결정적 사실이 나왔다: 검사기의 신규
   규칙(`annotation-record-unbound`)은 **정체성이 없는** 레코드만 잡으므로, 정체성이 한 번
   찍히면(어떤 경로로든) **exit 0 PASS**. 즉 그 차단은 "아무도 id 를 써 넣지 않는다"에 전적
   의존 — 이걸 확인해야 "무엇이 실제로 막고 있는가"를 정확히 쓸 수 있다.
3. **★ 구조 검사(자리별 대응)는 "살아 있지 않은 이름표는 건너뛴다 + 순서는 범위 안만 본다"가
   급소.** `captureCorrespondence` 류 방어의 우회법: 현재 범위 텍스트가 저장 `exact` 의
   **문자 부분수열**이면(예: `Cure` ⊂ `Critical failure` → 자리 0,13,14,15) 범위 안 문자를 그
   자리에 넣고, 나머지 자리는 **문서 다른 곳에서 그 자리의 글자와 같은 글자**로 채운다 →
   내용·유일성·순서 전부 성립, `surviving-characters` 로 부착(실측 오해소 1, 스토어 왕복도
   동일, `wouldFlipUpgradePathExists: true`). B4형(아무 문자로 padding)만 막혔다는 뜻.
   ⇒ "N종 모양에서 오해소 0"류 게이트는 **모양 수와 선정 근거**를 함께 읽어야 한다.
4. **★ 순서 의존을 없앴다면 다음 표적은 집합 의존·층간 불일치**다. 실측 3종:
   - `--annotations` 로 **넘긴 스토어만** 본다 → 같은 documentId 스토어 둘 중 `bound` 쪽만
     물리면 끊긴 종단점이 다시 사라진다(exit 0, broken 0). 같은 파일을 두 번 넘기면 **위양성**
     중복 위반(경로 개수로 셈). ⇒ 게이트는 **발견(discovery)**이어야 한다.
   - 검사기가 "투영 모양"(앵커 없는 레코드)을 허용하면 **`anchors` 필드를 지우는 것만으로**
     정체성 검사 자체를 건너뛰어 종단점이 묶인다 — 편집기는 그 스토어를 거절하는데
     게이트는 PASS(관대한 쪽 불일치). 검사기 자신이 "편집기가 거절하는 모양은 게이트도
     거절"이라고 적어 놨다면 그 문장이 곧 반례 탐색 지침.
   - **한 스토어 안 중복 레코드 id**: 검사기는 `bound` 쪽을 병합해 쓰고 편집기는 `find(id)` 로
     **파일 첫 레코드**를 쥔다 → 게이트가 "끊김 0"이라 서명한 링크를 편집기는 orphaned 로 연다.
     스토어 단위 중복만 막고 레코드 단위를 비워 두면 여기가 뚫린다.
5. **sticky 표식류 방어는 "표식이 실제로 막는가"를 따로 재라.** 옛 레코드에 **손으로**
   documentId 를 써 넣으면 표식을 남겨 둔 채로도 `unchanged-text` 예외로 cross-document 부착
   (검사기 exit 0). 막는 것은 표식이 아니라 정체성의 부재였다 = 자기보고 문구 정정 대상.
6. **쓰기/읽기 비대칭도 한 줄 시험**: `saveStore` 는 남의 문서를 주장하는 레코드를 **쓰고**,
   `loadStore` 는 그 파일을 **거절**한다(자기가 못 읽는 스토어를 쓸 수 있다).
7. 해제문 형식: (b) 조건부일 때 **"직전 판정이 걸어 둔 제외는 해제한다"를 명시**하고(자기
   기준 충족을 부정하지 않는다), 새로 찾은 것은 **차단 부활이 아니라 다음 wave 불변식 ≤3개**
   로 낸다 — 각 불변식에 "지금 값(실측) / 충족 기준(수치)" 두 칸.

## §10 — 5차 재판정 (바인딩 불변식 I-1~I-3: 게이트·편집기 등가 / 레코드 유일성 / 스토어 발견)

"직전 판정이 낸 불변식 N개를 닫았다"는 자기보고를 재는 판정. §9 의 절차에 더해 얻은 것:

1. **★ 역패치 반사실을 트리 사본에서 돌릴 때 `HO_TOOLS_DIR` 이 없으면 인과를 놓친다.**
   `rsync` 사본의 `check_links.py` 는 `REPO_ROOT/TOOLS_DIR` 를 **자기 위치 기준**으로 잡아
   `ontology_lib` 를 못 찾고 **exit 2** 를 낸다 → 반사실 전부가 "checker: exit 2, pass null"
   로 나와 *현상이 재현되지 않은 것처럼* 보인다. 반드시
   `export HO_TOOLS_DIR=<repo>/tools` 를 걸고, 프로브는 `ROOT`/`CHECKER` **상수만 sed** 로
   사본에 겨눈다(프로브 자체는 무수정 보존).
2. **★ 발견(discovery) 기반 게이트는 세 가지를 따로 재라.** ① 진짜 훑는가 — 저장소의 **다른
   곳에 스토어를 심어** 발견 목록에 뜨는지 보고 즉시 지운다(하드코딩 판별). ② 위양성 —
   같은 파일 2회 지목(realpath 정규화)·무관한 문서의 형제(끌어오면 안 됨)·정상 트리 대조군.
   ③ **발견의 전제**를 깨라: 파일 **이름**(`annotations.json` 아니면 안 보임), **격리 표식**
   (`.annotation-store-quarantine` 한 줄로 디렉토리 통째 제외 → exit 1·broken 1 이 exit 0·
   broken 0 이 된다), **작업공간 루트**(`.git` 조상이 없으면 범위가 인자 수준으로 되돌아가
   집합 의존 은폐가 부활). 셋 다 문서·게이트에 전제로 적혀야 "무력화"라고 쓸 수 있다.
3. **★ "게이트=편집기 등가" 주장은 편집기의 throw 조건을 코드에서 전부 뽑아 표로 만들어
   대조**한다. 실제로 뚫린 자리 둘: (i) 게이트가 `document.json` 을 **아예 읽지 않는다** →
   정직한 스토어를 남의 문서 옆으로 **이동**(병합·rename)하면 편집기는 거절, 게이트는 exit 0
   (복사면 중복 documentId 로 잡히고 **이동만** 뚫린다 — 두 변종을 반드시 갈라 재라). 평문
   `document.json.documentId` vs 스토어 `documentId` 비교로 닫히는 구멍이므로 "CRDT 를
   파이썬이 못 읽어서"는 변명이 안 된다. (ii) `isinstance(record["id"], str)` 로 **조용히
   건너뛰는** 레코드(id 가 숫자·부재·레코드가 객체 아님)를 편집기는 계약 위반으로 거절.
4. **★ 신뢰 경계 문단 판정 = 바깥 행을 실측으로 재현해 보는 것.** "막을 수 없다"고 선언한
   행을 프로브로 **실제로 성공시켜** 보면(예: 죽은 이름표 padding → 부착 성공) 그 선언은
   정직한 것이고 결함이 아니다. 반대로 안쪽 표의 **완결성 부사**("전부 막는다", "무력화")는
   반례 하나로 무너지므로 거기에 CONFIRMED 를 건다 — 경계가 넓혀졌는지(숨김)와 목록이
   불완전한지(문구 정정)를 **분리해서** 판정한다.
5. **분류 요구가 있는 브리프**((가) 일상 경로 / (나) bearer 경계 밖)에서는 "스토어 **파일**을
   쓰는가"가 갈림선이다. **저장소에 파일을 추가**하는 우회(격리 표식)는 스토어 쓰기가 아니라
   경계 문단이 포괄하지 못한다 → (가) 쪽 CONFIRMED.
6. 무회귀 baseline 이 **중간 상태 커밋**일 때: 그 산출물이 이전 커밋과 **byte 동일**한지 먼저
   확인하고("그 파일만은 안 움직였다") baseline 으로 쓴다. 구조 diff 는 `walk()` 재귀로 전
   경로를 찍어 "이번 델타뿐"을 눈으로 확인(집계 비교 금지).
7. 잔 함정: `anchorStateOf(session, anchors)` 이지 `anchorStateOf(resolveResult)` 가 아니다 —
   틀리면 프로브가 전부 `orphaned`/`broken 1` 로 나와 증거가 약해진다.

## §11 6차 재판정 — "사례가 아니라 **성질**로 닫았다"는 주장의 판정법

developer 가 계열을 **성질 테스트**(예: `게이트 accept ⟺ 편집기 accept` 를 fixture 전수에
자동 적용)로 닫았다고 보고할 때. 판정은 "성질이 초록인가"가 아니라 **성질이 성질인가**다.
네 질문을 각각 실험으로 답한다 (전부 트리 사본에서: `rsync -a --exclude node_modules tools/`
+ `ln -s <repo>/…/node_modules` + `mkdir .git` — 작업공간 루트 발견이 repo 와 같아진다).

1. **자동 포함**: **내가 직접 fixture 를 심어** 코퍼스 수가 늘고(33→34) 그 자리에서 FAIL 하는지
   본다. 심을 모양은 **두 언어의 의미 차이**가 최고다 — `anchors.legacy: []` 는 **JS truthy /
   Python falsy** 라 한 줄로 층을 가른다(같은 계열: `{}`, 빈 문자열, 숫자 0 의 취급).
2. **우회 배치**: 코퍼스 필터를 코드에서 읽어 그 **밖**에 두어 본다. `looksLikeStore`
   (`Array.isArray(annotations) && 'version' in payload`)가 필터면 `annotations` 를 객체로 만든
   fixture 는 **계약에 규칙이 있는데도 한 번도 측정되지 않는다**(스위트는 57/57 PASS 그대로).
   코퍼스 밖 디렉토리에 두면 성질은 못 보지만 **발견**이 판정해 다른 검사들이 붉어진다 —
   "성질만 피했다"와 "조용히 통과했다"를 구분해서 적을 것.
3. **비공허**: accept 쪽 대조군을 **내가 다시 세어** 낸다(계약 함수를 직접 import 해 코퍼스를
   재현: 33 중 accept 22 / refuse 11). 스위트 자체의 vacuity 가드(`refused >= 4`)는 약하다.
4. **인과**: 방어를 **한 줄씩** 되돌린 사본 두 개(`copy2`: fail-closed 제거, `copy3`: 문서 대조
   제거)를 만들어 (a) 원래 결함이 exit 0 으로 부활하는지 (b) **성질이 그것을 잡는지** 둘 다 본다.

**★ 성질의 급소 = 오라클 선택.** 성질이 "편집기 쪽"을 **진짜 loadStore 가 아니라 계약 함수**로
계산하고, 그 함수에 **게이트가 쓰는 입력**(옆 `document.json` 의 평문 필드)을 먹이면, 두 층의
입력이 갈리는 축은 구조적으로 안 보인다. 실증법: 진짜 `loadStore` 가 **거절하는** 스토어를
fixture 로 심었는데 성질이 `0 divergence` 를 내면 그것이 결함의 증거다(실측: 34 스토어, PASS).
계량도 함께 — 코퍼스 33 중 옆에 `document.json` 이 있는 스토어 **2개**, 진짜 loadStore 로
대조되는 스토어 **1개**뿐이었다.

**그 축에서 나온 (가) 계열 3형(전부 게이트 exit 0 · pass true · 종단점 묶임 / loadStore 거절)**:
`document.json` **없이** 스토어만 이동(내보내기·백업·gitignore) · 그 파일에 **평문 documentId 가
없음** · 그 파일이 **깨진 JSON**. 뿌리는 하나 — 레코드 축에는 fail-closed 를 적용하고 **문서
축에는 fail-open**(`_document_state_id` 가 `None` 을 반환하면 대조를 건너뜀). 방어가 "필드가
있으면 비교한다" 모양이면 **필드 없음/읽기 실패**를 반드시 따로 재라(대조군: 필드가 있으면
exit 1 인 것을 같이 보여 인과를 고정).

**부수 급소 — 자기검사가 항진명제인 경우.** "읽은 레코드 수 == 스토어가 실은 수" 같은 자기검사는
카운터를 **검사 앞**에서 증가시키면 **절대 발화하지 않는다**. 역패치로 skip 을 되살린 뒤 그 값이
**그대로인지** 확인해 반증한다(실측: exit 0 인데 `annotationRecordsRead` 7 로 동일). 보고 문구가
그 카운터를 근거로 들면 note.

**발견(discovery)의 sniff 예산은 수치로 깨 본다**: 머리 4096 바이트 안에 두 키를 요구하면
**키 정렬 직렬화 + 레코드 9개**로 `"version"` 이 byte 8326 으로 밀려 이름 바꾼 쌍둥이가 다시
숨는다(대조군: 정렬 안 하면 byte 4 → exit 1 · broken 1). 문서가 그 전제를 적었으면 CONFIRMED 가
아니라 **전제의 실제 값**으로 낸다.

착수 조건은 **2개 이내·수치**로: ① 세 모양 전부 exit 1 + negative control 3건(각 위반 1건)
② 성질의 편집기 쪽을 진짜 `loadStore` 로 (내 반례 fixture 가 divergence 로 잡히고, loadStore 로
대조되는 스토어 ≥3). 경계 바깥(H2·B5·Z1)·문구 note 는 차단 사유로 쓰지 않는다.
