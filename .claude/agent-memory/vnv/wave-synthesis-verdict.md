# 웨이브 종합 판정(하위 vnv 판정 N건 통합 + go/no-go) 절차

대상 유형: orchestrator가 하위 dispatch 판정 여러 건(예: 문서 매핑 / 온톨로지 반영 / JS
프로토타입)을 끝내고 **wave 전체 verdict + 다음 Phase go/no-go + 결정 요청 후보**를 요구할 때.
사례: `docs/verify/plane-editor-wave-synthesis.md` (④ webui/tiptap lane, Phase 0+온톨로지+Phase 1).

## 대원칙 — 종합은 재요약이 아니라 "하위가 못 본 축"을 새로 재는 일이다

하위 판정은 각자 자기 산출물만 본다. 종합에서만 가능한 측정이 넷 있다.

1. **로드맵 원본 대비 커버리지 표.** 설계 원본(§로드맵)의 단계를 행으로 놓고 "덮음/잔여 +
   대응 산출물 + 대응 GAP 번호"를 채운다. 잔여 단계에 **브리프 파일이 실제로 존재하는지**를
   `ls docs/plans docs/feedback/inquiries` + `grep -rl "Phase N"`로 확인 — "다음 단계가 계획돼
   있다"는 말은 거의 늘 미작성이다.
2. **하위 판정이 표본으로만 닫은 사각을 전수로 닫기.** (본 사례) 앵커 스위트 채점기가
   텍스트 동일성만 보는 취약성 → 하위는 표본 2건만 위치 재채점. 종합에서는
   ① **모호하지 않은 행들로 좌표 변환식을 먼저 실증**(`from = textOffset + blockIndex + 1`,
   ProseMirror top-level 블록 문서; 60행에서 예외 0) → ② **기대 문자열이 2회 이상 등장하는
   시행만** 추려(= 두 채점이 갈릴 수 있는 유일 집합) 전수 재채점. 42 텍스트-기대 시행 중 7건뿐
   이라 비용이 거의 안 든다. **편집이 없는 시나리오(S8)는 `docTextAfterEdit`가 JSON에 없으므로
   원 fixture 텍스트로 별도 채점**해야 빠뜨리지 않는다.
3. **게이트 문구가 레인/스코프 선택에 좌우되는지.** "생존 100%"가 pipeline(편집 후 재캡처)
   레인 선택의 산물이면 그 100%는 저장 selector 내구성이 아니다. 뿌리를 **브리프 문구 결함**
   (캡처 시점 미규정)으로 귀속시켜 적고, 확정을 orchestrator 결정 항목으로 올린다. 같은 렌즈로
   G3(같은 프로세스 2회=약함), G4(스위트가 `external`로 회피), G5(손저작 파일만 스캔)를 훑으면
   "자기 산출물만으로는 증명 안 되는 게이트"가 줄줄이 나온다.
4. **무주인(unowned) 잔여 식별.** 각 하위 판정의 note 중 "별도 lane 권고"로 넘긴 것들이 실제로
   어느 브리프에도 없으면 그게 wave의 진짜 구멍이다(본 사례: GAP A3 문서 정정, tokenEstimate
   예산 정확도 lane, Phase 0 정밀도 note 5건 미수정, node 스위트 CI 미포함).

## go/no-go를 수치로 쓰는 법

- **차단 범위를 "의존 시점"으로 한정한다.** "Phase 2 전체 보류"가 아니라 "**앵커가 링크
  종단점이 되는 작업만** 차단, 저장소 스키마·평면 저작은 비차단". 이렇게 쪼개야 조건이
  실행 가능해진다.
- 조건은 **재현 가능한 게이트 형태**로: "신규 시나리오 S9/S10을 스위트에 추가하고 전 레인
  오해소 0 / ≥12시행" + **현재 실측치 병기**(S9 2/2 오해소, S10 1/2) — 미충족임을 숫자로 못박는다.
- 실패의 **성질**을 구분해 적는다: 1자 경계 드리프트(위치는 맞음) vs 남의 문장 부착(오해소).
  전자는 no-go 근거가 아니다.

## 도구·명령

- 프로토타입 산출물 재현: 다른 세션에서 `node <suite>` 실행 후
  `git show HEAD:<artifact> | sha256sum` 대조 + `git diff --stat -- <dir>` 빈 출력 = N번째 독립 재현.
- CI 커버리지 확인은 워크플로 yml 직접 읽기 — Python 게이트만 있고 node 스텝이 없으면
  "재실행 byte-identical" 주장은 **CI로 강제되지 않는다**(비차단이나 반드시 기록).
- 하위 판정이 남긴 적대 스크립트(`docs/verify/*-adversarial.mjs`)는 **그대로 재실행**해
  결함 주장이 세션 간 재현되는지 본다(재현되면 결함 확정, 안 되면 하위 판정 뒤집기).
- 생성물(REPORT.md 등)의 문구 결함은 **문서가 아니라 생성기(src/report.mjs) 수정 대상**임을
  명시해야 후속 dispatch가 엉뚱한 파일을 고치지 않는다.

## 결정 요청 후보 압축(최대 3건)

"사용자만 결정할 수 있는 갈림길"만 남긴다 — 선택지 (a)(b)(c)와 **각 선택의 대가**를 붙이고,
부수적 확정 사항(예: 게이트 레인)은 가장 가까운 결정에 흡수시킨다. 후보 소스 3곳:
① 스키마 한계(range/chain 때문에 표현 불가한 것 — `ho:anchorTarget` range=Concept, rollup
chain이라 harness-level anchor 불가), ② 그래프-밖 저장소 위치(도구가 `ontology/`만 스캔하므로
무엇을 어디 두느냐가 강제력을 가른다), ③ 규약 vs 실사용 불일치(어느 쪽을 정본으로 삼을지).
