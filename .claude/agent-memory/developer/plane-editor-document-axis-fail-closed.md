# 문서 축 fail-closed + 성질을 자기 재계산에서 떼어내기 (tools/plane-editor)

앞 파일 `plane-editor-close-the-family-with-a-property.md`의 다음 단계. 판정(vnv 6차)이 남긴
조건 둘의 뿌리는 하나였다: **fail-closed 원리를 레코드 축에만 적용하고 문서 축에는 적용하지
않았다.** 그리고 그 사실을 성질이 못 본 이유는 **성질의 편집기 쪽이 진짜 편집기가 아니었기**
때문이다(계약 함수를 게이트와 **같은 입력**으로 재계산).

## 1. 성질의 오라클은 **재계산이 아니라 실제 경로**여야 한다

계약 함수를 다시 부르는 성질은 두 층의 입력이 갈리는 축을 **구조적으로** 볼 수 없다. 수정은
`loadStore`를 `inspectStore(dir, {storeFile})` 위에 세우고(첫 위반에서 던지는 대신 전부 모음),
성질이 그것을 부르게 하는 것. 그리고 **같은 자리에서 `loadStore` 자체도 불러** 두 답이 같은지
확인하는 체크를 하나 더 둔다 — 그것이 "오라클이 다시 재계산으로 퇴화하는 것"을 막는 유일한
구조적 장치다. 실증(역패치 대조군 2종):

- 게이트 규칙만 되돌림 -> C9 **divergence 4** (문서 축 fixture 4개가 editor rejects/gate accepts).
- 편집기 오라클을 옛 방식으로 되돌림 -> 대조는 **0 divergence(눈이 멂)** 인데 "편집기 쪽이 진짜
  loadStore인가" 체크가 **FAIL하며 그 4개를 이름으로 부른다**.

성질 테스트에는 vacuity 가드 말고 **범위 가드**도 둔다: "문서 축으로 거절되는 스토어 >= 3"
같은 축별 최소 개수(그 코퍼스가 비면 계열이 다시 안 보인다).

## 2. 스토어는 파일이 아니라 **디렉토리**다

`loadStore`는 `annotations.json` 옆 `document.json`을 먼저 연다. 그러니 게이트도 그 자리를
평가해야 한다: 없음 / 파싱 불가 / 문서 상태(`yUpdateBase64`) 없음 / (종단점을 묶는 스토어인데)
평문 `documentId` 없음 = 네 사유 전부 위반(`annotation-store-document-unreadable`). 앞의 셋은
**파일을 옮기는 것만으로** 도달한다.

두 층이 문서 정체성에 대해 **공유하는 표면은 평문 필드**다(게이트는 CRDT를 해독하지 않는다).
편집기가 그 평문을 CRDT에 못 박으면(mismatch 규칙) 게이트의 평문 대조 = 편집기의 판단이 된다.
그래서 **payload 계약에 넘기는 권위 id도 평문**이어야 규칙 이름까지 두 층이 일치한다(CRDT id를
넘기면 평문 부재 시 게이트가 낼 수 없는 mismatch를 편집기만 내서 divergence가 난다).

- 평가 **순서**도 두 층이 같아야 한다: 스토어를 통째로 못 읽는 코드(버전·annotations 배열·v3의
  자기 documentId)가 나오면 게이트도 거기서 멈추므로, 편집기도 그 뒤 축(문서·레코드)을 평가하지
  않는다. `STORE_UNREADABLE_CODES`로 명시.
- 평문 요구는 **종단점을 묶는 스토어**(v3+documentId)에만. 안 그러면 하위호환 진단(D4: 정체성
  이전 세대의 문서 상태를 손으로 만들어 로드)이 깨진다.
- 게이트가 원리적으로 못 보는 코드는 지우지 말고 `GATE_BLIND_CODES`로 **표시**해 `<gate-blind>`
  로 대조한다(그 모양이 코퍼스에 들어오면 divergence로 드러난다 = 전제가 코드에 산다).

## 3. 그 대가: fixture도 **실제 스토어 모양**이 돼야 한다

문서 축을 닫으면 `annotations.json`만 있는 fixture 30여 개가 전부 위반이 되어 "위반 정확히
1건" 대조군이 무너진다. 해법은 규칙 완화가 아니라 fixture를 디렉토리로 만드는 것:
**생성 스크립트**(`make-fixture-documents.mjs`, 표 = 디렉토리->documentId 단일 정의처, `--check`
로 디스크본 대조)로 실제 세션의 CRDT 상태를 써 넣는다. 평문만 담은 껍데기로는 진짜 `loadStore`
로 대조할 수 없다(그것이 애초에 성질이 눈멀었던 이유의 절반).

- 생성물은 결정론(clientID·documentId·본문을 표에 고정) -> 2회 실행 byte 동일.
- 새 소스 파일은 `src/language.mjs LISTED_FILES` 등록(G5), fixture json은 디렉토리 훑기라 자동.
- 스위트 무회귀 주장은 여전히 "scenarios/lanes/totals/diagnostics 동일 + **G5 파일 수만** 증가".

## 4. 잔손

- 성질의 코퍼스 필터를 게이트 발견 필터보다 **한 칸 넓게**(`annotations` 키가 있으면 배열이
  아니어도 후보) 두면, 계약의 첫 규칙처럼 필터에 걸려 한 번도 측정되지 않던 규칙이 측정된다.
  그 모양은 게이트에서 exit 2(지목한 읽기 불가)로 나오므로 `stopped` 처리와 짝이 맞는다.
- 옛 세대 레코드는 `anchors`가 아예 없을 수 있다 -> 강등 경로가 **던지면** 안 된다(계약 위반이
  아니라 프로그램 오류로 두 층이 갈린다). null-safe 접근으로 막는다.
- 판정 JSON에는 위반일 때만이 아니라 **언제나** 축의 상태를 싣는다(`documentState: readable`) —
  "그 축을 보긴 봤는가"가 산출물에서 확인돼야 한다.
- 문서 파일 이름은 두 층 다 **상수**로 안다(스토어의 `document` 필드는 아무도 읽지 않는다).
  그 규약을 바꾸려면 두 층을 함께 바꿔야 하고, 한쪽만 바꾸면 성질이 깨진다 — README에 명시.
- 완결성 문구는 성질로 옮긴 뒤에도 **범위**(코퍼스·필터·gate-blind)를 같이 적어야 한다. "성질이
  서면 새 변종은 자동으로 잡힌다"는 여전히 과장이다 — 자동인 것은 **코퍼스에 들어온 모양**뿐.
