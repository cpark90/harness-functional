# 개념 facet 축(B1) — 속성으로 계층화, 셰이프/린터 분담, 검색중립 측정

`ho:conceptFacet`(anatomy|quality|method|domain|scope) 도입 실측. 재사용 가능한 부분만.

## 1. 계층은 노드가 아니라 **속성**으로 (깊이 0)

`skos:broader` 검색 가중은 0.5다 — 기존 top들 위에 facet 노드를 씌우면 개념 간 발견성이
**절반**이 되고, 이미 예산 포화(896/900)인 팩이 관련 개념을 흘린다. 그래서 "층"이 필요할 때
먼저 **닫힌 값 datatype property**로 선언할 수 있는지 본다. TBox 정의문·파일 배너·해당 절
주석 세 곳에 "루트를 씌우지 말라"는 이유를 남겨야 다음 세션이 되돌리지 않는다.

## 2. 판정은 **규칙 순서 + 부모 우선 타이브레이크**로 (예시 나열 금지)

닫힌 값의 정의문에 "무엇의 이름인가"를 묻는 **순서 있는 테스트**를 쓴다(부위/구조축 →
주제분야 → 내용없는 구성형태 → 하네스가 갖춘 성질 → 명령형 행동규칙). 예시만 적으면
저자마다 유추가 갈린다. 두 테스트가 동시에 맞는 term(예: "grounding"=성질이자 실천)이 반드시
나오므로 **타이브레이크를 명문화**한다: `skos:broader` 부모의 값이 후보에 있으면 부모 것을
택한다 → 판단 하나가 기존 가지를 쪼개지 않고 그래프 변경량이 작게 유지된다. **재부모화는
부모의 테스트를 전혀 만족 못 할 때만**(anatomy 부모 아래의 실천 term). "내용 없음"류 값
(scope)의 부모는 자식을 구속하지 않는다고 함께 적어야 자식 12개가 줄줄이 재부모화 후보가
되는 오해를 막는다.

## 3. **셰이프=연합 불변식 / 린터=중앙 규약** (minCount 판단의 기준)

`ontology/shapes/`는 중앙 전용이 아니다 — data repo(harness-recipes)의 CI가 **중앙
validate.py + 이 shapes로 자기 union**을 검증한다(`HARNESS_CATALOG`/`HARNESS_ROOT_ONTOLOGY`).
그래서 새 술어에 `sh:minCount 1`을 걸면 **중앙만 바뀌었는데 하위 repo 전체가 깨진다**(실측:
recipe 로컬 `ho:Concept` 239개가 facet 없음). 판단 기준:
- **값 집합·개수(`sh:in`/`maxCount`)는 shapes** — 어디서 저작되든 지켜야 할 불변식.
- **존재(coverage)는 `tools/lint_uniformity.py`** — `str(n).startswith(str(lib.ID_CORE))`로
  중앙 네임스페이스에 스코프. recipe CI는 린터를 돌리지 않으므로 오탐 0.
선택한 쪽의 근거는 shape 주석 + 린터 docstring + ONTOLOGYSTYLE 문장 세 곳에 같은 말로 남긴다.

## 4. 검색중립 측정법 (전후 팩 비교의 실제 절차)

- **datatype property 선언은 검색에 무영향**: `link_predicates`는 ObjectProperty만 모으고,
  `node_text_fields`는 prefLabel/altLabel/definition/promptText만 읽으며, `token_cost`는
  tokenEstimate(없으면 15) 고정. 실측 16질의 팩 **16/16 byte-identical**.
- 팩을 움직이는 것은 **엣지 변경뿐**. 재부모화 3건만으로 16질의 중 2건이 달라졌다.
- **최소 델타 재부모화**: 새 부모로 `skos:broader`를 옮기고 **옛 부모는 `skos:related`로 남긴다**
  (0.5→0.4). 실측 — 순수 이동(A)은 한 질의에서 노드 3개가 팩에서 탈락, related 유지(B)는
  같은 질의에서 **탈락 0**(순위만 밀림), 다른 질의 1건에서 노드 1개 교체. SKOS적으로도 맞다.
- 절차: ①편집 전 baseline 팩 저장 → ②속성만 적용해 동일성 확인 → ③엣지 변경 variant별 비교
  → 델타를 "무엇 때문인지" 1:1로 귀속시켜 보고. baseline을 다시 뽑아야 하면 편집본을
  scratchpad에 복사해 두고 파일을 잠깐 되돌린다(병행 세션 있으면 즉시 복원).

## 5. 대량 편집은 스크립트 + **역-스트립 바이트 검증**

84개 블록에 술어 하나를 붙이는 편집은 스크립트로 하고(블록 종료 줄 `... .` 탐지, 100자 초과면
다음 줄로), 끝나면 **정규식으로 새 술어만 제거해 baseline과 byte 비교**한다 — "의도한 트리플만
추가됐다"의 유일한 기계적 증거. 매핑 dict은 전수(누락/중복) 검사 후에만 파일을 쓴다.

## 6. "결정 보류(pending)" 주석은 같은 웨이브에서 갱신

앞선 웨이브들이 남긴 "facet 결정이 보류라 평면 유지" 주석 3곳이 결정 직후 곧바로 stale이 된다.
결정이 land되면 그 문장들을 "속성으로 결정됐으므로 깊이 0을 유지"로 바꾼다(§1d: 대화성·이력성
주석 금지). 섹션 배너가 옛 부모를 열거하고 있으면 그 목록도 같이 고친다.
