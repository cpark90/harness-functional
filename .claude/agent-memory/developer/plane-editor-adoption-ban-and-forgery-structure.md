# 입양 금지(sticky) + 증거를 개수 대신 구조로 — plane-editor N-1~N-4 (tools/plane-editor)

vnv 바인딩 준비 판정이 **(b) 조건부 해제**로 내린 뒤 남긴 후속 조건 4개를 닫으며 배운 것.
앞선 파일 `plane-editor-identity-and-store-contract.md`의 다음 단계다(그 파일의 §2 "동거는
외부 사실이므로 강등본에도 붙인다"는 **여기서 뒤집혔다** — 그 한 줄이 세탁 경로였다).

## 1. 동거는 정체성이 아니다 — 입양 금지는 저장을 건너서도 유지돼야 한다(sticky)

정체성 없는 레코드에 "이 스토어 옆에 있다"는 이유로 스토어의 documentId를 찍어 주면,
**위조 없이** 남의 문서 레코드가 된다: 문서 A의 v1 주석 파일을 문서 B 옆에 두면 규칙 0이
불일치를 못 보고(불일치가 없다) 완전일치 예외로 부착되며, 편집기가 평범하게 load->save 하면
v3 레코드로 승격돼 링크 종단점이 된다. 방어는 세 겹을 **함께** 놔야 뚫리지 않는다.

- 강등 함수는 레코드가 **스스로 실은** 문서 id만 유지한다(스토어 값을 인자로 받지 않는다 =
  찍어 줄 방법 자체를 없앤다).
- 저장은 승격 지점이 아니다: `document: null` + 강등 표시를 그대로 쓰고, 로더는 그 조합을
  받아들이되(레코드를 잃지 않는다) **표시 없이 정체성만 없는** 레코드는 계약 위반으로 거절한다.
  쓰기 함수에도 같은 가드를 둔다("왜 미상인지 말하지 못하는 미상 레코드는 만들지 않는다").
- 링크 검사기도 그런 레코드를 종단점으로 받지 않는다(전용 규칙). 런타임만 막으면 커밋
  게이트가 통과시킨다.

**하위호환 경로가 vacuous해지는 것을 막는 법**(옛 실수의 반대편 함정): 시나리오는 강등 함수를
직접 불러 쓰므로 레코드가 자기 id를 유지해 여전히 guard까지 간다. 파일 경로 진단(D4)은 규칙 0
에서 멈추므로 **같은 세션·같은 문서의 정체성 있는 레코드**를 대조군으로 함께 재야 "전부 거절로
얻은 0"이 아님을 말할 수 있다. 진단이 세탁 경로 전체(load -> save -> reload)를 재게 만들면
게이트가 그 성질을 매 실행 지킨다.

## 2. 자기보고 증거는 **개수**가 아니라 **구조**로 검사한다

"이름표 길이 합계 == 저장된 exact 길이" + "캡처 SV 기준 preexisting" 두 검사는 마이그레이션
실수만 잡는다. 현재 교체 범위의 살아있는 이름표 + **문서 다른 곳의 이름표로 padding**하면 둘
다 통과한다(실측). 문서를 이기는 성질을 써야 한다: **CRDT 문자 item의 내용은 불변**이다.

- 캡처 런을 펼친 k번째 이름표는 `exact`의 k번째 문자를 가리킨다 → ① 그 이름표가 지금도 살아
  있으면 그 문자는 `exact[k]`여야 하고(문서 전역 대조), ② 이름표는 유일해야 하며, ③ 해소
  범위에서 살아남은 문자의 캡처 위치는 증가 수열이어야 한다. 셋 다 **사후 반증 가능**하다.
- 이 검사는 **해소 시점**에만 가능하다(현재 문서가 필요). 로드 시점 검사와 층이 다르므로
  진단·게이트도 두 수치를 **가려서** 보고해야 한다(로드 통과 N모양 / 해소에서 잡은 M모양 /
  끝까지 부착 0). 한 숫자로 뭉치면 "승격 경로 없음"이 측정 범위를 넘어 읽힌다.
- 증거가 위조로 반증되면 **완전일치 예외(unchanged-text)도 주지 않는다** — 한 레코드의
  자기보고는 함께 선다.
- 남는 구멍은 선언한다: 남의 문서의 **유효한** capture를 통째로 이식하면 대응이 전부 성립한다.
  서명이 없는 한 정체성은 bearer claim이고, 신뢰 경계는 "그 스토어 파일을 쓸 수 있는 주체"다.
  방어가 안 되는 문장은 문서에서 **정정**한다(옛 문구 "현재 상태에서 베껴 넣을 수 없다"는 반증됐다).

## 3. 색인 키 충돌은 덮어쓰지 말고 위반 + 보수적 병합으로

같은 documentId를 선언한 스토어 둘이 `(문서, 레코드)` 키를 덮어쓰면 끊긴 종단점이 **인자 순서에
따라 사라진다**(조용한 은폐). 문서 복제는 상태를 복사하므로 사고로 도달 가능하다.

- 중복 선언 자체를 위반으로 올리고(경로는 정렬해 detail에 싣는다), 상태는 **교환법칙이 성립하는
  병합**으로 합친다: 모름 > orphaned > bound. 그러면 어느 순서로 넘겨도 같은 판정이 나온다.
- 출력의 스토어 배열도 경로로 **정렬**한다 — 인자 순서가 판정 JSON에 새어 들어가는 마지막 통로다.
- 검증은 "같은 입력을 순서만 바꿔 두 번 돌려 JSON을 diff"로 못박는다.

## 4. negative control "위반 정확히 1건"을 유지하는 배치

새 규칙을 넣을 때 위반이 두 층(스토어 층 + 종단점 층)에서 동시에 터지면 대조군이 깨진다.

- 레코드가 남의 문서를 주장하는 경우: **스토어 층 위반만** 내고 색인에서 빼지 않는다(판정이
  이미 FAIL이라 조용한 통과가 아니다).
- 스토어 쪽만 망가뜨린 negative는 링크 스토어를 정상인 것으로 두고 `--annotations`만 바꿔
  물린다(대조군 표에 annotation 파일 목록 칸을 추가).
- 언어 정책 게이트는 fixture 디렉토리를 정렬 순회하므로 새 fixture가 자동으로 스캔된다 —
  산문에 `①` 같은 기호를 쓰면 그때 걸린다(허용 집합 밖). `(1)`로 쓴다.

## 5. 병행 세션이 작업 중간을 커밋할 수 있다

이번 세션 도중 inspection 세션이 mid-flight 트리를 커밋해 `git show HEAD:...` 기준 "변경 전"이
사라졌다. **baseline은 세션 시작 시 scratch로 복사한 산출물**이어야 한다(판정서의 sha256과
대조해 두면 더 좋다). 무회귀 주장도 그 사본 대비로 한다: 시나리오 배열·totals·bystanders·
placement·schema-dump·sample-state가 byte-identical이면 "진단/게이트만 움직였다"를 증명할 수 있다.
