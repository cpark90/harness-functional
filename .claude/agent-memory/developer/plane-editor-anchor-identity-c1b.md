# 앵커 복구는 "정체성"으로만 — plane-editor C1b (tools/plane-editor)

C1(문자 출처 guard + 블록 텍스트 기반 이동 복구) 이후 vnv가 오해소 4종을 더 CONFIRMED했다
(쌍둥이 블록 이동 / 원격 피어가 같은 문장 작성 / 삭제 후 재타이핑 / v1 레코드 하위호환).
넷을 닫으면서 배운 것 — 다음에 CRDT 위 앵커·링크를 만들 때 그대로 재사용된다.

## 1. 측정으로 끝내야 하는 질문: "이동"은 CRDT에 존재하지 않는다

y-prosemirror에서 블록 cut+paste는 **옛 YXmlElement 삭제 + 새 element 삽입**이다. 그래서
"블록을 옮긴 편집"과 "그 블록을 지우고 같은 문장을 다시 타이핑한 편집"은 **Yjs 업데이트가 byte
단위로 동일**하다 (`Y.encodeStateAsUpdate` sha256 동일 — 스위트 D3가 매 실행 재측정한다).

따라서:
- **텍스트 동일성 + freshness로 이동을 추정하면** 재타이핑·쌍둥이 이동·원격 작성이 전부 같이
  통과한다. 이것이 N1/N3/N4의 단일 뿌리였다 (증상 4개, 원인 1개).
- "저장된 blockContext.itemId를 후보 블록과 대조하라"는 지시는 **옳지만 오늘은 발동하지 않는다**:
  이동이 정체성을 파괴하므로 저장 id는 항상 tombstone이다. 그래도 그 조건으로 구현해 두면
  (a) 유일하게 증명 가능한 복구이고 (b) 블록 id 스키마·CRDT move 연산이 오면 자동으로 살아난다.
- **대가**: "블록 이동을 따라가는 복구"가 통째로 사라진다(S6 6앵커 × 2레인 = 12 레인측정이
  recovered -> orphaned). 이건 엔진이 혼자 못 고친다 — 문서 쪽 **안정적 블록 id**가 있어야 한다.
  브리프가 "오부착 불허 + orphan 허용"과 "이동 복구 유지"를 동시에 요구하면 그건 **모순**이므로
  측정치를 들고 보고한다(내가 고른 쪽: 절대 원칙인 오부착 불허).

## 2. 증거 없음(unknown)의 기본값은 **거절**이어야 한다

`survived = !origins.known || ...` 처럼 "모르면 통과"로 흐르는 기본값은 조용한 회귀 통로다.
실제로 강화된 guard가 **옛 레코드에서만** 무력화됐다(v1 파일에는 출처 증거가 없다).
- 뒤집을 때 recall이 죽지 않게 하려면 두 가지가 같이 필요하다:
  ① **완전 일치 예외** — 해소 텍스트가 저장 exact와 byte 동일이면 증거 없이도 채택(문자가 그대로).
  ② **증거 범위를 넓히기** — 출처 계산을 블록 1개가 아니라 **범위가 걸친 모든 블록**으로 확장
     (안 하면 문단 분할·블록 경계를 걸친 앵커가 전부 orphan이 된다).
- orphan 사유 문자열은 `content-replaced/unknown/legacy-v1-record`처럼 **왜 몰랐는지**까지 적는다.
  판정자가 집계만으로 원인을 가른다.

## 3. 저장 버전 bump는 "모양"이 아니라 "신뢰 수준"이 바뀔 때 한다

같은 `version: 1` 파일에 두 세대(3번째 selector 없음 / 있음)가 섞여 있으면 파일만 보고 가릴 수
없다 -> v1 전체를 **출처 미상으로 강등해서 로드**(레코드는 버리지 않음)하고 사유를 박는다.
`loadStore`가 `SUPPORTED_VERSIONS`로 읽고 `downgradeAnchors`로 강등, 미지원 버전은 계속 거절.
캡처 시점 state vector처럼 **캡처 이벤트의 성질**은 블록 문맥 안에 넣지 말고 레코드 최상위
(`anchors.capture`)에 둔다 — 안 그러면 블록 문맥이 없는 앵커가 증거를 통째로 잃는다.

## 4. 스위트에 새 계열을 들일 때 (S11 = N1/N1b·N3·N4·N8)

- **fixture는 파생으로 만들 수 있다**: "앵커마다 쌍둥이 블록이 하나씩" 같은 조건은 기존 fixture
  문서에서 앵커 블록을 복제해 파생하면 파일을 늘리지 않는다. `src/language.mjs`의 G5
  `AUTHORED_FILES`는 **손으로 나열된 목록**이라 fixture 파일을 새로 만들면 그 목록도 같이 고쳐야
  스캔된다 — 파일 소유가 다른 lane이면 파생이 충돌을 피하는 길이다.
- 앵커 id는 fixture마다 다른 접두사(b*/c*)로 나눠야 리포트 표·재채점에서 섞이지 않는다.
- **원격 피어 편집도 generic runner 안에서 된다**: `openSession({update})`로 peer를 열고
  `Y.encodeStateAsUpdate(peer.ydoc, Y.encodeStateVector(session.ydoc))` 델타만 applyUpdate.
- **옛 레코드 시나리오**는 시나리오에 `storeVersion: 1`만 달고, 러너가 저장소와 **같은 강등
  함수**로 레코드를 변환해 들이대게 한다(테스트 전용 복제본을 만들면 진짜 경로를 안 재게 된다).
- 함정: `session.schema.node(...)`로 만든 노드를 dispatch하면 PM이 그 트랜잭션을 **조용히 버린다**
  (편집기 스키마 인스턴스가 다르다). 반드시 `session.doc.type.schema`로 만들어야 하고, 안 그러면
  "재타이핑" 시나리오가 그냥 "블록 삭제"로 퇴화해 vacuous 초록이 난다. 시나리오를 넣은 뒤
  **문서 텍스트/업데이트 해시를 눈으로 확인**해서 편집이 실제로 일어났는지 봐야 한다.

## 5. 반사실은 양방향으로 잰다

`blocked`(약한 정책이었다면 났을 오해소)만 세면 "안전"만 자랑하게 된다. `forgone`(그 정책이었다면
**살렸을** 복구)도 같이 세서 리포트에 나란히 싣는다. 대조 정책을 하나 더 만들어(`textmove`)
버린 규칙을 계속 돌리면, 포기한 복구와 그 대가가 **같은 실행에서 한 표에** 나온다.
