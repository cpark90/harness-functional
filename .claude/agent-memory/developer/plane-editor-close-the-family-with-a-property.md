# 계열을 사례가 아니라 성질로 닫기 — plane-editor fail-closed + 발견의 전제 (tools/plane-editor)

앞 파일 `plane-editor-gate-editor-equivalence-and-discovery.md`의 다음 단계. vnv가 라운드마다
새 우회를 만들어 왔고(H3 -> H4 -> X1 -> X2), 그 넷의 원인이 하나였다: **게이트는 자기가 완전히
해석하지 못한 것을 조용히 건너뛰고, 편집기는 같은 것을 거절한다.** 이번에는 사례를 막는 대신
성질을 세웠다.

## 1. 규칙 목록을 **한 모듈**로 떼고, 스위트가 두 층을 전수 대조한다

`src/store-contract.mjs` = 편집기와 커밋 게이트가 **같은 답을 내야 하는** 규칙만 모은 곳
(파일시스템을 모른다: 파싱된 payload + 권위 있는 documentId만 받는다). `loadStore`가 이 함수를
쓰고, 스위트 C9가 **fixture 디렉토리를 훑어** 모든 스토어에 대해 `게이트 accept <-> 편집기
accept`를 대조한다. 새 fixture는 자동 포함이고, 불일치 하나면 FAIL.

- 두 언어라 함수를 공유할 수 없으므로 **코드 -> 게이트 규칙 이름 표**(`GATE_RULE_OF`)를 함께
  두고 그 표로 대조한다. 한쪽에만 규칙을 더하면 성질이 그 자리에서 깨진다.
- 성질의 **범위를 문서에 적어야 한다**: 대조는 "스토어 하나의 계약"이다. 스토어 **사이**의
  사실(같은 documentId 스토어 둘)·링크 종단점 해소는 `loadStore` 하나가 볼 수 없으므로 제외하고,
  게이트 위반은 **경로 귀속**으로 필터한다(detail에 repo 상대경로가 들어 있다).
- 성질이 vacuous가 아님을 같은 스위트에서 잰다(거절되는 스토어 수 >= 4). 그리고 계약 함수가
  **진짜 loadStore**와 어긋나지 않는지 실사용 스토어 하나로 못 박는다.
- 성질 테스트가 **내 설계 버그를 즉시 잡았다**: 옮겨진 스토어에서 레코드 대조 기준을 "권위 있는
  문서 id"로 두면 레코드마다 위반이 복제된다. 기준은 **그 레코드의 스토어가 선언한 값**이어야
  하고, 스토어가 아무것도 선언하지 않을 때만 권위 값으로 내려간다.

## 2. fail-closed = "평가 불가는 결과 없음이 아니라 위반"

`isinstance(record["id"], str)`로 건너뛰던 자리가 전부 구멍이었다. 규칙: **해석하지 못한 레코드는
위반**(객체 아님 / id가 문자열 아님·없음). 이름을 못 읽는 레코드는 파일 안 자리(`#3`)로 부른다.
그리고 판정에 "건너뜀"이 없다는 것을 **자기검사**로 못 박는다 — 해석한 레코드 수 == 스토어가 실은
레코드 수가 아니면 StoreError(그 수를 `counts.annotationRecordsRead`로 공개).

## 3. 두 발견 회피(이름·격리)는 **이미 있던 닫힘**의 따름으로 닫힌다

새 규칙을 만들지 말고 "범위 안 문서를 선언한 스토어는 판정을 피할 수 없다"는 기존 fixpoint에
후보를 얹는다.

- **이름**: 작업공간 훑기에서 `annotations.json`이 아닌 `.json`도 sniff(머리 4KB에
  `"annotations"`·`"version"` -> 그때만 전문 파싱)로 **후보**에 올린다. 범위 안 문서면 끌려오고,
  다른 문서면 `outOfScope`에 사유와 함께 남는다. 저장소 72개 json 전수 sniff = 12ms.
- **격리**: 격리는 **자기 subtree 안의 문서에 대해서만** 유효하다. 그 문서를 격리 **밖에서**
  판정하는 스토어가 있으면 끌어온다. 이 한 줄이 fixtures 트리를 살린다 — 대조군의 문서
  (`doc-fixture-*`)는 격리 안에만 살기 때문에 계속 제외되고, 공격자의 쌍둥이는 밖에 짝이 있어
  끌려온다. (전역 규칙 "격리가 범위 안 문서를 가리면 위반"으로 만들면 negative control 19개가
  전부 깨진다 — 대조군 트리에 같은 documentId 스토어가 11개 있다.)
- 격리 후보를 **호출자가 그 디렉토리를 직접 지목해** 다시 찾으면 격리 표시를 지운다(지목은
  격리보다 세다). 이걸 빼먹으면 "형제 스토어 함께 판정" 대조군 2개가 조용히 죽는다.

## 4. 옮겨진 스토어(X1)는 CRDT 없이 **평문 두 필드**로 닫힌다

스토어의 `documentId` vs 옆 `document.json`의 `documentId`. 게이트는 CRDT를 해독하지 않으므로
평문끼리 견주고, 그 필드를 손으로 고치는 것은 경계 **바깥**이라고 적는다(구별은 CRDT 상태에만
있고 그것은 편집기 층이다). fixture는 `document.json`을 **평문 정체성만** 담아 만든다 —
`yUpdateBase64`가 없어도 게이트 규칙은 성립하고, 편집기 층은 계약 함수로 잰다.

## 5. 문서의 완결성 부사는 실측을 넘지 못한다

"안쪽은 전부 막는다"는 반증됐으므로 **"전부"를 지우고** 대신 (a) 목록은 실측으로 찾아 닫은
사례들이며 (b) 완결성은 성질(C9)로 주장한다고 적는다. 그리고 발견의 **전제 표**(이름 규약·격리
표식·workspaceRoot)를 만들어 각 전제가 완화됐는지/남았는지와 **깨지면 무엇이 되는지**를 적는다.
전제는 판정 JSON에 값으로 드러나야 하고(`workspaceRoot: null`), 스위트가 매 실행 실측한다(C10).
강화의 **대가**도 같은 표에 적는다(같은 문서의 백업 사본이 이제 duplicate-document가 된다).

## 6. 잔손 (이 lane 특유)

- 버전 상수를 계약 모듈로 옮기면 게이트의 드리프트 알람 정규식이 겨누는 파일도 함께 옮겨야
  한다(`ANNOTATION_PLANE_MODULE`) — `export { X } from ...` 재수출은 `export const X = 3`을 찾는
  정규식에 걸리지 않는다.
- 새 소스 파일은 `src/language.mjs`의 `LISTED_FILES`에 등록해야 G5 언어 게이트가 본다(fixture
  json은 디렉토리 훑기라 자동).
- 스위트 산출물의 무회귀 주장은 **시나리오·diagnostics·totals 동일 + G5 파일수만 증가**로 적는다
  (파일을 늘리면 G5 카운트는 필연적으로 움직인다).
- C9가 게이트를 스토어당 한 번씩 spawn하므로 링크 스위트 시간이 늘어난다(약 11s -> 25s). 커밋
  게이트 자체는 그대로 0.35s.
