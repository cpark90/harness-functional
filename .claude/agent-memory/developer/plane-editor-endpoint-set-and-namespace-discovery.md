# 집합을 세는 술어 · 이름 공간 · 사유의 층 (plane-editor 바인더 3건)

앞 파일 `plane-editor-binder-fail-closed-alone.md`의 다음 wave. 판정은 이미 "실사용 가능"
이었고 남은 것은 **비차단 관측 3건**이었다 — falsy 앵커·심링크 발견·전역 거절의 진단력.
셋 다 "무엇을 세는가 / 어디까지 보는가 / 무엇을 말하는가"의 문제였고, 다른 lane에도 그대로 온다.

## 1. 두 층이 같은 집합을 세려면 **판정 술어**까지 같아야 한다

게이트는 `"anchor" in ep`(키의 존재)로, 바인더는 `if (!ep.anchor)`(truthiness)로 종단점을
갈랐다. 같은 어휘·같은 목록을 쓰는데도 `anchor: ""`·`0`·`null`은 **한 층에서만** 종단점이었고,
바인더에서는 "레코드만 가리키는 종단점"으로 강등돼 `anchorEndpoints 0 · unbound 0`이 됐다.
없는 것과 거절한 것이 같은 숫자로 보이면 거절은 측정되지 않는다.

- 값이 **선언**인 자리(이름·부분·종류)는 **키의 존재**로 판정한다(`Object.hasOwn`). 값의
  truthiness는 "비어 있음"과 "없음"을 뭉갠다.
- 이 결함은 사유 목록으로는 안 보이고 **집합 크기**로 보인다. 그래서 대조군마다
  `anchorEndpoints 1 · recordEndpoints 0`을 함께 재게 했다 — 사유 1건만 보면 "종단점이 아예
  없어서 사유도 없다"와 구별되지 않는다.
- **대조군 생성기의 판정 기준도 대조군의 일부다.** 스위트의 `linkStoreAt`이 `anchor ? {anchor} : {}`
  였기 때문에 애초에 falsy 축을 **지을 수 없었다**. 생성기가 truthiness면 그 축은 영원히 빈칸이다.

## 2. 발견은 **이름 공간**을 따라간다 (심링크), 정규화가 그 대가를 막는다

격리 표식·파일 이름으로는 못 숨는데 디렉토리 심링크로는 숨었다: 정직한 스토어를 작업공간
밖에 두고 이름만 링크로 들여오면 사본만 범위에 남아 **사본의 답**이 초록으로 나갔다(vnv Y6).
`os.walk`는 기본이 `followlinks=False`다.

- 자체 `_walk`로 디렉토리 심링크를 따라가되 **실경로 visited 집합**으로 사이클을 끊는다
  (이 저장소에도 루트를 되가리키는 심링크가 있다: `staging/harness-recipes/central`).
- 디렉토리가 아닌 항목은 전부 `filenames`로 낸다 — 깨진 심링크를 조용히 건너뛰면 "이름이
  `annotations.json`인데 못 읽으면 멈춘다"는 fail-closed가 풀린다.
- 따라가는 순간 **가짜 중복**이 위험이 된다(같은 실체의 두 이름). 경로가 발견에 들어갈 때
  realpath로 정규화되면 그대로 하나다. 두 방향을 **한 쌍의 검사**로 둔다: 숨을 수 없다 +
  가짜 중복이 없다. 대가(작업공간 밖 심링크는 그쪽 트리도 훑는다)는 문서에 적는다.
- **비공허성 시험법**: 두 안전장치(심링크 visited·take의 realpath)가 서로를 덮으므로 한쪽만
  되돌린 반사실은 초록이다. **둘 다 끈** 반사실에서 비로소 FAIL한다 — "덮는 장치가 둘이면
  대조군도 둘을 꺼야 한다"를 반사실 설계에 적어 두는 편이 낫다.

## 3. 전역 거절은 판정은 유지하고 **사유만 층으로** 늘린다

링크 하나가 나빠 평면이 거절되면 나머지 종단점의 사유가 전부 평면 사유 하나로 통일됐다.
고치고 싶은 유혹은 "더 좁은 사유를 top-level `reason`으로 올리기"인데, 그러면 앞 wave가 세운
**우선순위 배치**(좁은 것 -> 넓은 것)와 그 위에 선 대조군이 깨진다.

- `reason`은 소비자 계약이므로 **건드리지 않는다**. `reasons.{endpoint, plane}` +
  `gateViolations`를 **추가**한다. 자기 잘못이 없는 종단점은 `reasons.endpoint: null`.
- 짝짓기는 게이트가 판정 JSON에 실어 준 필드(`record`=링크 id, `endpoint`=`plane:ref`)로만
  한다. detail 산문을 뒤지면 남의 층 문장에 의존하게 된다.
- 진단 층은 **열지 않고** 계산할 수 있는 것만 담는다(`storesOpened 0`은 그대로 유지).
- 검사는 "세 종단점이 **세 답**을 낸다"로 세운다(자기 잘못 없음 / 좁은 가드 / 이 링크가 원인).
  층을 평평하게 만든 반사실에서 그 검사만 FAIL한다.
- 같은 masking이 **사람이 읽는 표**에도 있었다: 열지 않은 스토어를 "아무 종단점도 필요로 하지
  않음"으로 찍으면 평면이 빨개서 못 연 스토어가 "필요 없었다"로 읽힌다. 거절 행이 스토어
  이름을 싣고 있으므로 그것으로 갈라 찍는다.

## 4. 잔손 (이 lane 반복)

- 산출 불변이 최고의 증거다: 이번 변경은 **실사용** `bind-links --format json`·게이트 JSON을
  byte-identical로 남겼다(거절 행에만 필드를 더했고 bound 행·top-level은 그대로). 스위트
  산출은 G5 `asciiChars`/`hangulChars` 둘만 달라진다(산문 증가) — 해시가 아니라 필드 1:1 diff로 보인다.
- 대조군 바닥값은 33 -> 34로 올린다(추가는 허용, 감소는 FAIL). `BINDER_NEGATIVE_CONTROLS.length >= 4`
  처럼 **부류별 하한**도 함께 걸어야 "게이트 대조군을 늘려 바인더 대조군 감소를 가린다"가 막힌다.
- vnv 프로브는 자기가 아는 필드만 투영한다(`link/anchor/reason`). 새 필드를 더해도 그 산출에는
  안 보이므로, 새 성질은 **스위트 안에서** 재고 보고에 "프로브 투영에는 안 보인다"를 적어 준다.
