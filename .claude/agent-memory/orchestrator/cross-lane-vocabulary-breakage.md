# 중앙 어휘를 폐기하면 그래프 밖 소비자가 조용히 깨진다

**사실**: `validate.py`는 `ontology/`만 스캔한다. 따라서 중앙 TBox에서 술어·클래스를 폐기하면,
그것을 소비하는 **그래프 밖 코드·데이터**(도구, 별도 평면 저장소, 하위 repo)의 파손을 중앙
게이트는 **영구히 감지하지 못한다**. 중앙이 초록인 채로 소비자만 빨갛게 남는다.

이 세션 실제 사례: `ho:Anchor`·`ho:alternativeOf`·`ho:overlapsWith`를 폐기했더니 다른 lane의
`check_links.py`(하드코딩 어휘 목록)와 `links.json`(그 어휘를 주장하는 레코드)이 깨졌다.
vnv가 cross-lane grep으로 잡아 **차단 결함**이 됐다.

**어떻게 적용**:
- **폐기를 포함하는 브리프에는 cross-lane 잔존 소비자 grep을 게이트로 넣는다** — 중앙 abox·
  shapes·tools뿐 아니라 `tools/<다른 lane>/**`, 하위 recipe repo, `docs/**`, published clone까지.
- **코드를 고쳐도 데이터는 따라오지 않는다.** 소비자 정리는 코드/데이터 두 갈래를 따로 확인한다.
- 소비자 쪽 올바른 형태는 **어휘 목록을 베끼지 않고 살아 있는 그래프에서 파생**하는 것이다.
  그러면 어휘 추가·은퇴에 게이트가 **양방향으로** 따라간다(병행 세션이 이 형태로 전환).

**교훈 문장**: *다른 층의 어휘를 목록으로 베끼면 그 층이 바뀔 때 조용히 깨진다 — 출처를 가리켜야
한다.*
