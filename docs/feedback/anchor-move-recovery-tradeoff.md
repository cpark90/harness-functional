# 결정 요청 — 블록을 옮기면 주석이 orphan이 된다 (되살리려면 문서 스키마 결정이 필요)

## 무슨 일이 일어났나

편집기 앵커 엔진에서 **오해소(주석이 엉뚱한 텍스트에 붙는 것)를 0으로 만들었더니, 블록을
잘라 붙여 옮겼을 때의 복구가 6/6 → 0/6(전부 orphan)으로 사라졌다.** 이것은 버그가 아니라
**원리적 한계**이고, 두 dispatch가 각각 독립으로 측정해 확인했다:

- 블록 **cut+paste 이동**과 "블록 삭제 후 같은 문장 **재타이핑**"은 **Yjs 업데이트가 byte
  단위로 동일**하다(sha256 동일, 결과 문서도 동일). y-prosemirror에서 이동은 "옛 element
  삭제 + 새 element 삽입"이라 **정체성이 파괴**되기 때문이다.
- 따라서 **"재타이핑에는 붙지 않는다"** 와 **"이동은 따라간다"** 는, 저장된 상태만 보는
  어떤 규칙으로도 **동시에 만족할 수 없다**.
- 대가는 계량됐다: 이동 복구를 살리는 정책이면 **복구 12건을 얻고 오해소 36건을 얻는다.**
  현행(정체성 기반)은 **복구 0·오해소 0**이다.

지금은 승인된 원칙("orphan은 허용, 엉뚱한 위치 부착은 불허")에 따라 **복구를 포기**한 상태다.
이 결정은 되돌릴 수 있으나, 되살리려면 아래 중 하나를 골라야 한다.

## 선택지

- **(a) 현행 유지 (권고)** — 블록을 옮기면 그 블록의 주석은 orphan이 되고, 사용자에게 명시
  표시된다. 오해소 0을 지킨다. 대신 "문단을 옮겼더니 주석이 다 떨어졌다"는 경험이 남는다.
- **(b) 문서 스키마에 안정 블록 id를 넣는다** — 각 블록이 편집을 넘어 유지되는 id를 갖게 하면
  이동과 재타이핑이 구별되어 **복구와 오해소 0을 동시에** 얻는다. 비용: 문서 스키마 변경이므로
  기존 문서의 마이그레이션이 필요하고, 편집기 밖에서 만든 문서에는 id가 없다. (주의: 이것은
  "문서 스키마에 **주석용** mark/노드를 두지 않는다"는 원칙과는 별개 사안이다 — 블록 id는
  주석이 아니라 문서 자신의 속성이다.)
- **(c) CRDT의 진짜 move 연산을 쓴다** — Yjs가 이동을 1급 연산으로 표현하면 정체성이 보존된다.
  비용: 해당 기능의 성숙도·호환성을 먼저 조사해야 하고, 편집기 스택 선택에 영향을 준다.

## 참고

- (b)·(c) 중 하나를 고르면 **Phase 2 이후 스키마 결정**으로 편성한다. (a)를 고르면 현행이
  그대로 확정되고, orphan 가시화(어느 주석이 왜 떨어졌는지 표시)가 대신 중요해진다 —
  그 작업은 이미 진행 중인 wave에 포함돼 있다.
- 이 항목과 별개로, 앞선 항목 `plane-editor-and-kg-content-decisions.md`의 **결정 5·6은 아직
  미응답**이다(overlapsWith 2쌍 저작 여부 / `AlternativeOfSharedAnchorShape` 강화 방식).
  특히 결정 6은 승인된 문구가 "정의 유사도 하한"인데, 이 lane의 실측이 **유사도 축으로는
  오부착을 막을 수 없다**는 것을 보였으므로(같은 함정), B1 facet이 서면 **판별 축을 facet
  공유로 바꾸는 대안**을 함께 검토하시길 권한다.

## (c) 선행 조사 결과 (inspection, 2026-08-28 — 성숙도·호환성 실측 조사)

(c)의 전제 조사를 수행했다. **결론: (c)를 Yjs 위에서는 할 수 없고, 하려면 Loro로의 스택
교체가 필요하다. 한편 (b)의 비용이 당초 평가보다 낮음이 확인돼 재고를 권한다.**

- **Yjs 경로 막힘**: Yjs는 **v14에서 move 지원을 중단하기로 결정**했다(iterator 중심 코드베이스
  전반의 복잡도 + 낮은 사용률). v14.0.0-1의 move 구현은 **배열 corruption 이슈**(#694)까지
  보고됨. v13의 move는 실험 단계로 남았고 공식 권장은 "기존 프리미티브로 move 의미를 우회
  구현"이다. → 현 스택(yjs+y-prosemirror) 위에서 (c)는 성숙도 기준 미달.
- **Loro 경로 성숙**: Loro는 **movable list가 1급 연산**(MovableListState, `insmov` 통합
  연산)이고 **공식 ProseMirror 바인딩**(loro-prosemirror)이 있다. 단 비용 = 앵커 엔진의 CRDT
  스택 교체(RelativePosition 대체·영속 포맷 변경·Phase 1 스위트 재검증 전면).
- **(b) 재평가**: 안정 블록 id는 **Tiptap UniqueID 확장이 MIT(무료)** 로 존재한다(유료 경계는
  Comments/AI Toolkit 쪽 — 기존 조사 dossier와 교차 확인). 기존 문서 마이그레이션은 1회성
  id 부여, 외부 문서는 id 없음 → 현행 orphan 동작으로 자연 강등. 항목 본문이 인정하듯 (b)는
  **이동 복구와 오해소 0을 동시에** 얻으며, 스택 교체가 없어 Phase 1 검증 자산이 유지된다.

**권고**: **(b)로 전환** — 같은 목표(이동 시 주석 생존 + 오해소 0)를 스택 교체 없이 달성하는
더 싼 경로가 열려 있다. (c)를 유지하려면 **Loro 교체 wave**(앵커 엔진 재작성 + S1–S10 전면
재검증)로 편성해야 한다. 선택지를 갱신하면:
- **(b′) 안정 블록 id (권고)** — Tiptap UniqueID(MIT), 스키마에 블록 id 속성 추가 + 마이그레이션.
- **(c′) Loro 스택 교체** — move가 1급인 CRDT로 이행; 별도 wave 규모.

어느 쪽이든 Phase 2 이후 스키마 결정으로 편성한다(항목 원문과 동일). 아래에 (b′)/(c′) 중
선택을 남겨 주면 해당 브리프를 준비한다.
